## P1 — High severity

### P1-A: Hydration mismatch on `/precedents` causes HMR cascade bouncing all routes

**File:** `qgi-frontend/components/precedents/PrecedentsMergedListClient.tsx`, line 845
**Code:** `Generated {new Date(generatedAt).toLocaleString()} ·`

`toLocaleString()` is called without a fixed locale. The server (Node.js) formats the date in the system locale (`10/05/2026, 00:37:29`) while the Playwright browser formats it differently (`5/10/2026, 12:37:29 AM`). This triggers a React hydration error on `/precedents` on every page load, which causes Next.js HMR Fast Refresh to fire repeatedly. In the Playwright test environment this cascades as an app-router re-render that navigates away from whatever URL the browser had just reached — making interactive testing of `/signals/india` and `/signals/india/[slug]` unreliable.

**Fix:** Replace with a fixed-locale string or pass a pre-formatted string from the server:

```tsx
// Before (line 845):
Generated {new Date(generatedAt).toLocaleString()} ·

// After (server-format, no locale drift):
Generated {new Date(generatedAt).toLocaleString("en-GB", { timeZone: "UTC" })} ·
// OR pass generatedAtFormatted as a prop from the server component
```

This bug is in `PrecedentsMergedListClient.tsx`, not in Signals — but it makes the Signals QA sweep significantly harder and will affect any real user on a non-en-GB system browsing through multiple routes.

### P1-B: Master list table rows link to `/signals?recipe=…` instead of `/signals/{country}/{slug}`

**File:** `qgi-frontend/components/signals/SignalsMergedListClient.tsx`, line 453
**Code:** `const detailHref = \`/signals?recipe=\${row.category}\` as Route;`

Every row in the 67-row master table and every card in the "5 firing now" curated band links to `?recipe=civil_war_and_insurgency` (the V1 query-param URL) rather than to `/signals/{top_country}/{category}` (the new canonical leaf URL). The per-country and per-leaf routes (`/signals/[country]/[slug]`) exist and work — but nothing in the master list routes to them.

The same issue affects the curated band (`FiringNowBand`, line 653: `const detailHref = \`/signals?recipe=\${live.category}\``).

**Impact:** Users on the master list cannot reach the new Family 3 leaf pages via any click path from `/signals`. The cross-family handoffs footer on the country watchlist and leaf correctly links back to `/signals`, so the reverse direction works. But forward navigation (list → leaf) is broken.

**Note:** The PR #4 comment in `SignalRowComponent` says "PR #3 is now landed" but the routing still uses V1 URLs. This needs updating to the canonical leaf path before cutover.

## P2 — Medium severity

### P2-A: Master list search input missing `aria-label`

**File:** `qgi-frontend/components/signals/SignalsMergedListClient.tsx`, lines 317-329
**Code:** The `<input>` has `placeholder="Search category or domain..."` but **no `aria-label`**.

The per-country watchlist (`SignalsCountryDetail.tsx`, line 384) correctly has `aria-label="Search category or L1 domain"`. The master list does not. This causes the PR #46 verification to fail specifically on the master list.

Screen readers on `/signals` will announce the input as unlabelled. The placeholder is not a substitute for an accessible label.

**Fix:** Add `aria-label="Search category or domain"` to the input element (line 322 of `SignalsMergedListClient.tsx`).
