## P1

### P1-A — Not-found page has no app shell body (missing `not-found.tsx`)

`/patterns/nonexistent-pair-1900-1901` triggers `notFound()` correctly (title becomes `Pattern not found — QGI Intelligence`, sidebar renders), but the main content area is empty — there is no custom `not-found.tsx` under `app/(app)/patterns/` or `app/`. The user lands on a shell with just the sidebar and an empty `<main>`. No "try another pattern" prompt, no link back to `/patterns`.

- **Fix**: add `app/(app)/patterns/not-found.tsx` (or a global `app/not-found.tsx`) with a brief "Pattern not found" card + back link.
- **HTTP status**: returns 200 in dev; `notFound()` correctly produces 404 in production builds, so HTTP is not a separate bug.

### P1-B — `4 unique pairs · 250 pattern instances` — ranking data is narrow

The live `data/ranking.json` (baked 2026-04-30) contains 1,000 rows but only **4 unique country pairs** (Paraguay–South Korea dominates with ~240+ instances; Nepal–Portugal, Nepal–Spain, Nepal–South Africa fill the rest). The eyebrow hardcodes "156 countries · 13 locked recipes · 60 years of data" (correct — that's the corpus size) but the dynamic subtitle line "4 unique pairs" looks wrong to any user who reads it. This is not a code bug — the server-derived `uniquePairCount` is accurate for the current bake — but it creates a misleading user impression.

- **Immediate**: acceptable for preview; the "cutover pending sign-off" banner covers it.
- **Before cutover**: ranking.json should be refreshed from a full bake, or the subtitle should say "pattern windows" rather than "unique pairs."

## P2

### P2-A — Tier-vocab strip dismissal is in-memory only (documented TODO)

The "Dismiss" button hides the strip for the session but a page reload shows it again. The code has a `TODO` comment noting this needs `useSearchParams` / URL-state wiring before PR #5 cutover. No user-visible regression; behaviour is already documented.

### P2-B — Sparkline `<span>` wrapper has title tooltip; SVG has `aria-label` — hover tooltip gap

The sparkline tooltip shows via `title="Preview trajectory — 7-point correlation series..."` on the `<span>`. On Windows/Chrome, `title` tooltips only appear after a ~1.5s hover delay. The `<svg role="img" aria-label="Pattern trajectory sparkline (preview)">` is correct for screen readers, but sighted users may not realize there's a tooltip unless they hover long enough. The brief asks for `aria-label` (present ✓) and "Preview trajectory..." text (present via `title` ✓). Functionally compliant.

### P2-C — Sort option "Window tier" deviates from test-plan label "Window tier" (match)

Test plan listed the sort option as "Window tier" — source uses exactly `<option value="window_tier">Window tier</option>`. ✓ No issue.

### P2-D — `generated_at` in detail page footer shows `2026-04-30` (stale bake)

Footer reads `V1.9.1 scoring · Generated 2026-04-30`. This is the real bake date from `ranking.json` (PR-iv Flavor A fix confirmed working). Data is stale but the date is accurate — no code bug.

## Notes on test methodology

The Playwright browser session was shared with another active session during this sweep, causing the browser to navigate away from `/patterns` on every `page.goto()` call before screenshot/snapshot could be captured. All interactive element testing (click states, hover tooltips, real-time filter narrowing, keyboard navigation) was therefore conducted via: (1) SSR HTML from `curl`+extract pipeline, (2) direct source-code review of `PatternsMergedListClient.tsx` and `PatternMergedDetail.tsx`, and (3) `ranking.json` data verification scripts. Browser-interaction findings (preset chip active state, tier-vocab dismiss visual, grid layout card rendering, sparkline hover delay) are assessed from source code and marked accordingly.
